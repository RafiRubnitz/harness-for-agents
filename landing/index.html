01 / what it is

An agent runtime you own, end to end.

harness is a desktop app and CLI that hosts a team of agents locally. You decide which model each agent uses, which tools it may touch, what it remembers and what has to be approved first.

[ conv ]

Own conversation

Every agent keeps its own history in SQLite, with crash recovery and context compaction.

[ model ]

Own model

Anthropic, OpenAI or DeepSeek per agent, through one gateway with retry, fallback and cost tracking.

[ tools ]

Own tools

Files, shell, web, memory, MCP servers and your own Python tools, hot loaded.

[ perms ]

Own permissions

A permission pipeline plus user hooks that allow, ask or deny every tool call.

[ mem ]

Own memory

Lexical search out of the box, vector search with a local BGE‑M3 embeddings server.

02 / quick start

From clone to first agent in three steps.

You need Python 3.12 and uv. Everything the harness writes lives in ~/.harness/; set HARNESS_HOME to move it.

// let an agent do it

Install with an AI agent

Copy the install guide and paste it into Claude Code, Cursor or any coding agent with a shell. It installs everything end to end, verifies each step, and asks you to enter API keys yourself.

View install.md
1

Install

Clone the repository and let uv create the environment and install every dependency.

git clone https://github.com/RafiRubnitz/harness-for-agents
cd harness-for-agents
uv sync
2

Add an API key

Keys live in the OS keyring under the service harness, never in files. Names: anthropic, openai, deepseek, and optionally firecrawl for the web tools. The GUI settings dialog stores them the same way.

uv run python -c "import keyring; \
  keyring.set_password('harness', 'anthropic', 'sk-...')"
3

Run it

Open the desktop GUI to manage many agents at once, or chat with a single agent straight from the terminal.

uv run harness                # desktop GUI (Tkinter)
uv run harness chat           # one agent in the terminal
uv run harness chat --new --model main
uv run harness agents         # list agents and status

04 / architecture

Small components, strict boundaries.

Front ends never reach into the internals. They send commands and listen for events; the dispatcher turns commands into calls, and import contracts enforce the layering in CI.

harness.core

Core

Types, commands, events, records and errors. Imports no other component.

harness.agents

Agents

The agent loop, runs, inbox, approvals and crash recovery.

harness.models

Models

One gateway over Anthropic, OpenAI and DeepSeek: streaming, retry, fallback, cost.

harness.context

Context

Builds each model request, with compaction and stored tool results.

harness.tools

Tools

Registry, permission pipeline, safe execution and background tasks.

harness.memory

Memory

SQLite history, blobs, semantic memory on LanceDB, embeddings server.

harness.hooks

Hooks

User hooks from hooks.yaml: Python functions or commands.

harness.config

Config

Layered YAML (global, project, agent), secrets, templates, hot reload.

harness.gui · harness.cli

Front ends

Desktop GUI and terminal chat, talking only through commands and events.

harness.app

Composition root

Wires everything together; harness.dispatcher routes commands.

GUI / CLI→ command →dispatcher→agents · tools · models→ event →GUI / CLI
05 / extend

Tools and hooks, your way.

Built in: files (read, write, edit, grep, list, delete with backup), shell, memory, web, plus the always‑on context and tasks groups. Everything else you add yourself.

Custom tools

Drop a Python file into ~/.harness/tools/. It is picked up without a restart.

from harness.tools import tool


@tool(group="dev", read_only=True, default_permission="allow")
async def count_lines(path: str) -> str:
    """Count the lines of a file."""
    ...

MCP and background tasks

  • MCP servers under mcp_servers: in config.yaml, as a stdio command or an HTTP url. Their tools appear as mcp.<server>.<tool> and ask before running.
  • Background runs: any tool call can carry run_in_background: true. The agent gets a task id at once and a <background_task_done> message when it ends.
  • Semantic memory: uv sync --extra embedder enables vector search with BGE‑M3 (about 2.3 GB on first use), or point embedder.url at a server you already run.

Hooks decide what runs

Hooks in hooks.yaml run a Python function or a command on agent events, and can match on tool, agent, template, path glob or source type. Before a tool call, every matching hook returns a decision and the strictest one wins. If a hook fails before a tool call, the default is to deny.

allow

The call runs straight away.

ask

The agent pauses until you approve it in the GUI or terminal.

deny

The call is blocked and the agent is told why.

06 / develop

Checked on every change.

Tests never touch the network or a real model: providers, the embedder and the web are replaced by fakes and mock transports.

uv run pytest                                  # tests, coverage must stay >= 80 %
uv run ruff check . && uv run ruff format --check .
uv run pyright
uv run lint-imports                            # the architecture contracts
uv run python scripts/acceptance_report.py     # spec acceptance criteria -> tests
! status

This is an MVP (v0.1.0). There are no live tests yet, so nothing in the repository has been run against a real provider. Expect rough edges and please open an issue when you hit one.
